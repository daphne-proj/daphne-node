## Design basis

A structurally valid partition is necessary but does not establish useful grouping. Grade required dependencies, separation of unrelated responsibilities, evidence-grounded explanations and honest uncertainty. The first implementation measures the first two semantic properties against human labels; a calibrated LLM judge for explanations/uncertainty is a later extension, not a prerequisite for usable deterministic evaluation.

Start with ten reviewed cases, then grow toward 30–50 when the pipeline is useful. These are development milestones, not statistical guarantees. Cover cohesive changes, unrelated responsibilities within one file, cross-file correctness dependencies, implementation/test relationships, compatibility edits, metadata-only changes, empty input, insufficient context, multi-page analysis and fragmented hunks. Cases may cover multiple categories.

The current model sees supplied diff evidence, not the entire repository or PR discussion. Annotate missing context explicitly. Multiple partitions can satisfy the labels. Preserve ambiguous relationships instead of forcing one exact reference answer; do not use group count or title similarity as the primary quality score.

Use three trivial baselines: all units together, one group per unit, and one group per change/file. Compare them with the current model on identical cases. Run three independent full trials by default for an initial live experiment, with explicit concurrency `2`; allow positive integer overrides. These are initial operating defaults chosen for a small benchmark, not quality thresholds.

The [saved v3 example](../../../outputs/split-pr-20261023-192117-87636/run.json) can seed one candidate case if it remains available locally. It is ignored/untracked and therefore not a portable dataset dependency. Import only its evidence with provenance; its model proposal is not ground truth.

## Langfuse payload and measurement policy

Keep the original `run.json` and full evaluation trial artifacts locally. Langfuse receives an explicit projection through its native SDK fields:

| Destination           | Content                                                                                                                                                    |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Experiment item input | `caseId`, `inputHash`, pinned identity, inventory and original compact hunk evidence; one copy of source text                                              |
| Expected output       | Reviewed together/separate/unknown labels used by evaluators; never supplied to the splitter                                                               |
| Task output           | `SplitExperimentOutput`: `{ status: 'complete', proposal: Proposal }` or `{ status: 'failed', error: { name: string, message: string } }`; sanitize errors |
| Native scores         | Acceptance/constraint metrics and diagnostic call/correction counts, attached by evaluators                                                                |
| Native observations   | Experiment/workflow duration and per-call start/end times; generations carry native `model` and `usageDetails`; counting calls are ordinary spans          |
| Native cost           | Langfuse's estimate from the generation model, usage and configured matching prices; unavailable when usage/pricing is missing                             |
| Custom metadata       | Daphne identifiers, hashes, versions, partition/trial and run configuration; no raw artifacts or duplicate native metrics                                  |

Raw provider payloads, encrypted reasoning, replay histories, duplicated page text and top-level response copies remain local. Construct allowlisted objects instead of spreading full results into SDK calls. The built-in runner records task input/output; returning a full `SplitTrial` would export it even if evaluators need it only locally. Keep full trials in a run-local map for scoring.

`TokenUsage` stores inclusive provider totals as `{ inputTokens: number, outputTokens: number, cachedInputTokens: number | null, reasoningOutputTokens: number | null }`. Validate safe nonnegative counts and breakdowns no larger than their parent totals. `RecordedModelCall` stores `{ kind, number, model, startedAt, endedAt, elapsedMs, status, usage: TokenUsage | null }`; timestamps are ISO UTC strings and `usage` is null for counting calls. It contains no raw provider response.

At the Langfuse boundary, convert known cached/reasoning breakdowns into non-overlapping native buckets: subtract cached input from `input`, subtract reasoning output from `output`, and send the details separately as `input_cached_tokens` and `output_reasoning_tokens`. Omit unavailable detail keys; keep `total` equal to inclusive input plus output. Missing/malformed provider usage is never replaced with the token-counter estimate. Include paid usage from rejected responses, and emit no duplicate generation usage on the root observation. Verify bucket names against the configured model prices; cost is an estimate with coverage limitations, not an invoice total.

## Contracts and scoring policy

All persisted formats are versioned and validated from `unknown` when read. Store compact hunks as `{ changeId, hunkIndex, sources }`, matching the current CLI representation. The future live runner will resolve them to `DiffContextHunk` through the validated inventory; offline commands do not need model input. Do not duplicate `Change` or `SourceEvidence` type definitions.

| Contract              | Required fields and meaning                                                                                                                                                                                                                                                                                        |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `SplitSuite`          | `format: 'daphne-split-suite-v1'`, nonblank `id`, ordered unique relative `caseFiles: string[]`                                                                                                                                                                                                                    |
| `SplitCase`           | `format: 'daphne-split-case-v1'`, stable `id`, `partition: 'development' \| 'holdout'`, `tags`, `provenance`, compact frozen `evidence`, `labels`, `notes`, `review`                                                                                                                                               |
| `PairLabel`           | `leftUnitId`, `rightUnitId`, `relation: 'together' \| 'separate' \| 'unknown'`, nonblank `reason`                                                                                                                                                                                                                  |
| `review`              | `{ status: 'draft' }` or `{ status: 'reviewed', reviewer: string, reviewedAt: string }`; never mark generated labels reviewed automatically                                                                                                                                                                        |
| `provenance`          | `{ kind: 'artifact', capturedAt: string, artifactSha256: string, sourcePrUrl: string \| null }` or `{ kind: 'synthetic', capturedAt: string, constructionSource: string }`; timestamps are ISO 8601 UTC and hashes are lowercase SHA-256 hex                                                                       |
| `PreparedSplitCase`   | `{ definition: SplitCase, caseHash: string, inputHash: string }`; the future live runner builds model input from `definition.evidence` only, excluding labels                                                                                                                                                      |
| `SplitTrial`          | `format: 'daphne-split-trial-v1'`, `caseId`, `inputHash`, `caseHash`, `trialNumber`, `variant`, `elapsedMs`, ordered `modelCalls: RecordedModelCall[]`, and serializable complete/failed `result`                                                                                                                  |
| Serializable `result` | Preserve pages, analyses, attempts, call counts, `maxCorrections`, accepted proposal/response and status from `SemanticSplitResult`; replace failure `error: unknown` with a sanitized `{ name, message }` without stacks/credentials                                                                              |
| `SplitScores`         | `completed`, `accepted`, `constraintsPassed` booleans; `firstReply: 'valid' \| 'invalid' \| 'no_reply' \| 'not_required' \| 'not_applicable'`; recovered flag; attempt/correction counts; separate together/separate `{ satisfied, total, rate: number \| null }`; violated pairs; proposal-validation diagnostics |
| `SplitRunManifest`    | `format: 'daphne-split-eval-run-v1'`, `suiteId`, `datasetHash`, `partition`, `variant`, `scorerVersion`, `startedAt`, `trials`, `concurrency`, `status: 'complete' \| 'incomplete'`, ordered `cases` and `issues`; use this same format for baseline and model runs                                                |
| Manifest `cases`      | One entry per scheduled case/trial: `{ caseId, inputHash, caseHash, trialNumber, trialFile: string \| null, scores: SplitScores \| null, issues: string[] }`; files are relative to the run directory. Missing work retains its entry and makes the run incomplete                                                 |

Define `variant` as `{ kind: 'model', model: string, maxInputTokens: number }` or `{ kind: 'baseline', strategy: 'all' \| 'unit' \| 'file' }`. Use the existing complete/failed discriminator for results; never invent a valid accepted proposal for a failed trial.

`caseHash` is SHA-256 of the exact case-file bytes, covering labels and provenance. `inputHash` is SHA-256 of a deterministic JSON projection of only identity, inventory and compact hunks, preserving arrays/source text and constructing object keys in a fixed order. `datasetHash` hashes a JSON array containing the suite-file hash and ordered `[caseId, caseHash]` pairs. Changing labels changes dataset/case hashes; regrading requires an identical input hash and records both old and new case/scorer versions.

The grading rules are fixed:

- Recompute expected IDs from inventory and validation from raw attempt text/accepted proposal; never trust saved `validation` or score fields.
- `completed` reflects workflow status. `accepted` requires `status: 'complete'` and a freshly valid accepted proposal. A failed result stays unaccepted even if a retained attempt validates.
- First-reply validity uses the first completed grouping reply, not the first generation call. Analyses and failed calls are not grouping attempts. Empty successful model input has `firstReply: 'not_required'`, zero attempts/corrections and a valid empty proposal. Baselines use `firstReply: 'not_applicable'` and are excluded from model-reply/recovery statistics.
- Corrections equal `max(0, attempts.length - 1)`; recovery means the first completed reply was invalid and final acceptance succeeded. This does not describe transport retries or independent trials.
- For accepted proposals, score each adjudicated unordered pair once. Unknown/missing labels are excluded. A label class with zero support has `rate: null`, never `1`. Reject contradictory pairs and a separate relation inside a transitive together component during validation.
- Invalid/failed output has unavailable pair rates and `accepted = false`. Define `constraintsPassed = accepted && all adjudicated pairs satisfied`; report label support so a no-label case cannot be presented as semantic-quality evidence.
- Aggregate acceptance/constraint-pass counts over all scheduled cases and trials. Publish conditional pair metrics with eligible/total counts and average per case; do not let large PRs dominate through pair count.

Langfuse custom metadata contains only case/dataset/input hashes, trial/partition, scorer/prompt version and run configuration such as the token budget; scores, timing, token usage and costs use native fields. Hash exported prompt strings plus proposal schema in fixed order. Initialize every requested case/trial entry before running; cancellation retains entries for later unstarted rounds. Exit `0` means evaluation completed with every scheduled case and score accounted for, even if model quality is poor; exit `1` means malformed input, interruption, missing results/scores, failed persistence or failed integration finalization. Always print quality failure counts separately. No unagreed semantic threshold blocks execution.
- [ ] **Step 8: Verify failure accounting offline, then run an explicit live sample.** Reject an empty selected partition before filesystem/credential/telemetry access. Use temporary assertions at the provider/telemetry boundary to exercise successful empty input, no-reply provider error, four invalid replies, fourth-reply recovery, cancellation after a valid draft, SDK task omission, scorer error and artifact-write failure. Expected: each scheduled case appears in the local manifest; errors never raise aggregate quality. Run `bun run check`, then during authorized implementation invoke one reviewed single-page case with `--trials 1 --concurrency 1`; verify its local artifact and Langfuse item/score readback. Model charges occur only in this explicit live command.
- [ ] **Step 9: Verify payload and accounting explicitly.** In temporary assertions, feed input tokens `100` with cached `20`, and output tokens `30` with reasoning `10`; expect native buckets `80 + 20 + 20 + 10 = 130`, never `160`. Verify missing usage remains unavailable, invalid/subset-exceeding counts are diagnosed, count-endpoint estimates add no consumed tokens, and usage from a response rejected by output validation is retained. Put unique sentinel fields/text in a full trial and assert they are absent from every exported input/output/metadata except explicitly selected evidence. Assert scores and native usage are outside task output, no root usage duplicates child usage, and callbacks are attributed to the correct case with concurrency `2`. Force recorder/export failures and verify the original model outcome remains local while the evaluation reports incomplete observability. During authorized live verification, inspect per-call durations, provider usage and model pricing in Langfuse; confirm readback contains only the allowlisted content and each call once. Record absent pricing/usage explicitly instead of claiming verified zero cost.

**Deliverable:** Repeatable experiments with compact Langfuse content, native scores/timing/usage/cost, durable full local outputs and honest incomplete-run reporting; no crash-resume promise. Suggested authorized commit boundary: `feat(eval): run semantic split experiments`.

### Task 4: Deliver offline regrading and fair comparison reports

**Files:** Complete `report.ts`; extend `contracts.ts`, `command.ts` and app documentation. Extract `comparison.ts` only if keeping loading/persistence and comparison in one file becomes hard to read.

**Interfaces:**

- `regradeSplitRun(suitePath: string, runDirectory: string, outputDirectory: string): Promise<void>`.
- `compareSplitRuns(baselineDirectory: string, candidateDirectory: string, outputDirectory: string): Promise<void>`.
- Both read versioned JSON through runtime validation, write new artifacts, and perform no network operations or credential lookup.

- [ ] **Step 1: Implement `split-pr regrade --suite PATH --run DIRECTORY --output NEW_DIRECTORY`.** Require every stored case ID to exist and every input hash to match; allow updated labels only while recording old/new case hashes and scorer versions. Recompute draft/final validation and all pure scores from saved output, retaining acquisition/provider/cancellation failures and original run issues. Reject corrupted or missing artifacts; do not silently score the subset that loaded. Regrade cannot turn an incomplete source run into a complete one.
- [ ] **Step 2: Implement `split-pr compare --baseline DIRECTORY --candidate DIRECTORY --output NEW_DIRECTORY`.** Require identical selected case IDs, input hashes, label/case versions, partition and scorer version; tell the operator to regrade both runs when labels/scorers differ. Compare each case's acceptance, pair rates and constraint-pass result, then aggregate per case. For repeated model trials report per-case distributions before cross-case means. One deterministic baseline may be compared against several model trials; do not count repeated baseline copies as independent evidence. Report case-level improved/regressed/unchanged outcomes and a readable table plus JSON.
- [ ] **Step 3: Report operational diagnostics honestly.** Include scheduled/completed/accepted counts, first-reply categories, recovery/attempt counts, observed single-page/multi-page/fragmented slices, elapsed times and call counts. Derive fragment status from repeated unit IDs across pages. Aggregate consumed usage from recorded generation calls exactly once, including responses rejected by provider-output validation; do not add page/attempt/top-level copies again. Publish observed totals and usage coverage separately; unknown usage prevents a claim of complete spend. Keep count-endpoint estimates separate from consumed tokens and report its call count/latency. Langfuse calculates estimated cost from native model/usage and matching configured prices; do not build a second pricing engine. Offline reports show cost as unavailable and link to the Langfuse experiment for its cost estimate; regrading performs no fetch or repricing. Total workflow timing includes counting, and per-call timing comes from the saved records. Missing pricing/usage remains unavailable, not zero.
- [ ] **Step 4: Verify offline independence and comparison integrity.** With model/Langfuse variables unset and network unavailable, regrade and compare the same saved artifacts twice; expect identical scores and stable case ordering. Change only labels and verify regrade preserves evidence/results while changing versioned scores; change an input byte and expect rejection. Exercise missing case files, unsupported versions, duplicate accepted responses, no usage, mismatched partitions and a valid draft retained under failed status. Format and run `bun run check`.

**Deliverable:** Useful local reports and cheaper iteration on scorers without repeated generation. Suggested authorized commit boundary: `feat(eval): regrade and compare saved split runs`.

### Task 5: Establish the initial benchmark and judge handoff

**Files:** Populate `apps/eval/datasets/split-pr/cases/*.json`; update `suite.json`, dataset `README.md`, app/root READMEs and current architecture/migration documentation.

**Interfaces:** Consume import/validate/baseline/run/regrade/compare commands. Produce a reviewed corpus, annotation rubric and baseline report whose limitations are explicit.

- [ ] **Step 1: Collect ten provenance-backed candidate cases.** Prefer representative real PR evidence; use clearly identified synthetic cases for hard structural conditions such as empty input or an oversized fragmented hunk. Freeze imported evidence locally rather than relying on moving URLs. Distinct revisions/variants of the same change belong to one partition. Record intended slices; observed paging depends on the run's model/budget and is measured separately.
- [ ] **Step 2: Annotate and review labels.** Document together/separate/unknown examples, grounded reasons, acceptable alternative partitions, absent context and the whole-hunk granularity limit. An engineer reviews each case; a second reviewer checks a subset and adjudicates disagreements. Generated suggestions remain `draft` until human review. Report the actual reviewed count; do not fabricate reviewers or claim ten reviewed cases when only candidates exist. Runner/scorer implementation can finish independently of corpus annotation.
- [ ] **Step 3: Separate iteration from held-out comparison.** Assign eight initial cases to development and two to holdout, keeping related PR revisions together. This is an initial operational split, not a statistical power claim. Never use holdout labels as prompt examples. Expand both partitions as the corpus grows toward 30–50 rather than continuously tuning against the same two held-out cases.
- [ ] **Step 4: Generate the first baseline comparison.** Run all three offline baselines over the reviewed development cases; run the current model with three independent trials during explicitly authorized model execution. Compare on the same case/label/scorer versions, inspect concrete regressions, and include representative successful/failed artifacts. Exercise a reviewed multi-page case live. Report constraint support and unavailable evidence; do not claim semantic correctness merely from coverage or a green smoke check.
- [ ] **Step 5: Write the next judge milestone without implementing an uncalibrated judge.** Specify three future rubric dimensions: responsibility coherence/separation, evidence-grounded dependency reasons, and useful uncertainty reporting. Human labels use pass/fail/insufficient-evidence, with raw hunks available to the judge. Require a separate calibration set, measure false acceptance and abstention, and compare blinded candidate order with ties allowed. Select judge/model/prompt and a practical agreement target only after reviewing labeled outputs. Keep this extension out of the initial acceptance gate; no opaque overall quality score or generic text-similarity dependency.
- [ ] **Step 6: Complete verification and independent review.** Format changed files, run `bun install --frozen-lockfile`, `bun run check` and `git diff --check`. Obtain an independent review of data leakage, denominator/support semantics, persistence failures and unchanged production behavior. Record the corpus's real review status and the exact live/offline checks performed. Preserve missing human annotations or unavailable credentials as explicit remaining work, not invented success.

**Deliverable:** A measured baseline and concrete next improvement targets. Suggested authorized commit boundary: `docs(eval): establish the split-pr benchmark`.

## Deferred extensions and evidence

- Add broader repository/PR acquisition checks separately through `splitPullRequest`; the initial quality benchmark deliberately freezes acquisition output.
- Per-call native observations are included now. Defer broader production tracing, full prompt/response capture on child spans, dashboards and a local cost-pricing engine.
- Add confidence intervals with PR-level resampling when the corpus supports meaningful comparisons. Do not treat hunk pairs or repeated runs of one PR as independent PR samples.
- Later product validation should measure reviewer corrections, comprehension/bug-finding and review time together. Structural/reference scores alone do not establish reviewer benefit.
- No patch application/buildability, fine-tuning, generalized clustering framework, automatic acceptance threshold, hosted dataset sync, CI paid jobs or production monitoring in this first slice.
